# 实战工作流

从一篇 AI 生成的论文到 10% 以下 AIGC 率的完整路径。

## 前置条件

```bash
pip install python-docx
```

## 完整流程（6 步）

### 第零步：收集真实研究细节

LLM 改写最大的天花板是"凭空编不出真实研究路径"。开始前先问作者：

1. 做项目时，**最初尝试过但放弃**的方案是什么？
2. **调参过程中**，哪个参数让你折腾了好几次？
3. **导师/老师**给过什么具体建议？
4. **实验跑到中途**，发现过什么意外现象？
5. **翻文献**时哪一篇影响最大？

挑能答的 2-3 个回答，每个 1-2 句话即可。

### 第一步：6 维诊断

对原 docx 通读，按段落输出 6 维评分（每维 0-2 分，命中 AI 信号给高分）：

1. **句长波动**（标准差 <3 给 2，3-6 给 1，>6 给 0）
2. **套话密度**（"首先/其次/综上"频次）
3. **三项排比**（"X、Y、Z" 出现）
4. **缺研究者主体性**（无第一人称叙事）
5. **思维过于均衡**（无转折/质疑/自我修正）
6. **风格一致性差**（伪口语化网络词混入学术语境）

总分映射：
- ★★★★★ 极高风险（9-12 分）
- ★★★★☆ 高风险（7-8 分）
- ★★★☆☆ 中风险（5-6 分）
- ★★☆☆☆ 低风险（3-4 分）
- ★☆☆☆☆ 安全（0-2 分）

### 第二步：等用户确认要改的段

明确询问：
> "请确认要处理哪些段落？(a) 只改 ★★★★ 以上 (b) 全部 ★★★ 以上 (c) 我指定 (d) 全文都改"

### 第三步：逐段改写 + 12 项自检

按 SKILL.md 的"三大铁律"改写：

1. **极致冗余**：同一概念用两种说法说一遍
2. **极致单调**：同段内同一个词反复用，不换近义词
3. **极致简单**：长句一逗到底，零破折号、零分号

每段改完照清单打勾（任一未通过立即重写）：

```
- [ ] 零破折号 ——
- [ ] 零分号 ；
- [ ] 零"这一X"、"这套X"、"那一X"
- [ ] 零"被X了"被动结构
- [ ] 零三项排比（哪怕用句号断开的"伪三项"也不行）
- [ ] 同一个核心词重复出现 ≥2 次（不换近义词）
- [ ] 至少 1 处"也就是说""换句话说""说白了""比如说"
- [ ] 至少 1 处第一人称"我"或"我们"
- [ ] 至少 3 处模糊限定词（比较/差不多/基本上/不太/挺）
- [ ] 至少 1 处冗余表达（同义重复一次）
- [ ] 没有"伪口语化"网络词（脚印/天花板/扛得住）
```

### 第四步：保留格式替换回原 docx

把改写后的 markdown 内容（按章节结构组织）保存到一个 .md 文件，然后：

```bash
python3 scripts/replace_docx.py 原.docx 改写后.md 输出.docx
```

脚本会自动处理：
- ✅ 按章节标题（Heading 样式）定位段落
- ✅ 保留表格、图片、引用上标 `[N]`、字体、目录、参考文献
- ✅ 跳过：声明、签名、英文摘要、关键词、Caption
- ✅ markdown 段数 > docx 容量时自动合并多余段
- ✅ 多格式段（关键词、Keywords 等）保持原结构

输出报告示例：

```
markdown 章节数：49
docx 章节可替换段数：
  [摘要] docx:1 md:4 ⚙ 自动合并
  [1.1研究背景与意义] docx:5 md:5 ✓
  [1.2.1传统机器学习方法] docx:2 md:2 ✓
  ...

=== 替换完成：102 段 ===

章节替换详情：
  ✓ [摘要] 替换 1/1
  ✓ [1.1研究背景与意义] 替换 5/5
  ...
```

### 第五步：检测反馈闭环

收到检测报告（PaperPure / 知网 / 维普）后：

1. **归因**：找出仍然 ≥ 20% AI 率的段落，反向定位到 docx 章节
2. **针对性二次改写**：对仍高的段，应用「进阶优化」（数字段模糊化、原理段加"我研究了一段时间才搞明白"、总结段加主观评价）
3. **重新替换 + 重新测**

### 第六步（可选）：嵌入真实研究细节

如果走完前 5 步仍然 > 10%，把第零步收集的真实细节定向嵌入到摘要、绪论、总结这三段最关键的位置。每段嵌入 1-2 句真实事实，能再降 3-5%。

例如：
> "在调参的时候我发现 max_len 这个参数挺关键，最早我按 TextCNN 原论文设的 100，后来发现中文邮件常常更长，调到 300 之后效果好了不少。"

LLM 编不出来这种细节，检测器也学不到反指纹。

## 验收标准

| AI 率 | 行动 |
|-------|------|
| **< 10%** | 完成，可交学校系统 |
| **10-15%** | 用户决定是否继续优化（边际收益递减） |
| **15-25%** | 继续 5、6 步循环 |
| **> 25%** | 检查是否漏改大段、检查 markdown 是否真按 v3 规则写 |
