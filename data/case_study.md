# 实测案例：从 55% 降到 11% 的完整迭代

> 真实毕业论文：《基于 CNN 的中文垃圾邮件分类系统设计与实现》（约 22000 字）
> 检测平台：PaperPure（aicheck.cnki.net 同类对抗训练检测器）
> 检测覆盖模型：GPT-3.5/4、Gemini、Claude、文心一言、通义千问、智谱 AI、豆包、Kimi、DeepSeek
> **最终结果：55% → 11%，降 44 个百分点，稳过 15% 红线**

## 迭代时间线

### v0：原始 AI 写的论文

- **AIGC 率：55%**
- 直接由 LLM 生成（未做任何处理）
- 这是基线 — 任何工具的"降幅"都从这里算起

### v1：用市面工具改的版本

- **AIGC 率：40.5%**（降 14.5 pp）
- 前部 20%：75.6% / 中部 60%：29.2% / 后部 20%：38.6%
- 摘要片段贡献最大 AI 字符数

**症状**：能看出已经做了同义词替换、句式调整，但 LLM 指纹依然明显。市面工具大多停留在表层。

### v2：错误模仿"半口语化"风格（反弹）

- **AIGC 率：49.6% ↑（涨 9.1 个百分点）**
- AI 特征字符数：8657 → 10374（涨 19.8%）
- 后部 20%：38.6% → **66.6%**（几乎翻倍）

**根因诊断**：

<!-- diagnose-skip-start -->
1. **破折号 `——` 滥用**：每段都有 1-3 个，是 Claude 4.5 头号指纹
2. **"这一X"、"这套X" 句式**："数据处理这一环""模型设计这一环"
3. **被动语态**："整条链路被走通了"、"被往前推了一步"
4. **"伪三项排比"**：用句号断开的"X。Y。Z。"仍是排比
5. **"X——Y" 短句**：表面句长波动，实则结构规整
<!-- diagnose-skip-end -->

**关键洞察**：用 Claude 写的"看似口语化"的文字，正好是检测器训练时见过的"AI 伪装人"模式。LLM 越想模仿人，越像 LLM 自己。

### v3：本科生答辩稿风格（成功）

- **AIGC 率：27.0% ↓（降 22.6 个百分点）**
- 仅改写 3 段验证（摘要 + 1.1 研究背景 + 6.1 总结），共约 3000 字
- 自检数据：26 处第一人称、8 处"也就是说"、41 处模糊限定词、零破折号

**做对了什么**：

| 指标 | v2（失败） | v3（成功） |
|------|-----------|-----------|
| 破折号 `——` | 满篇 | **0** |
| 第一人称"我/我们" | 0 | **26 处** |
| "也就是说/比如说" | 0 | **8 处** |
| 模糊限定词 | 少 | **41 处** |
| 三项排比 | 多 | **0** |

## 真实段落对比

### 摘要开头

**v1（其他工具改的）**：
> 中文垃圾邮件已成为网络信息安全领域的常见问题。尤其在中文场景下，邮件文本语义表达灵活、词语边界不明显，加之发送者常借助谐音替换、符号插入等手段规避过滤系统，使得传统方法难以满足实际应用需求。

**v2（错误尝试）**：
> 中文垃圾邮件的识别比想象中棘手。这类邮件不长，多则两三百字，少的只有一句。可发送者懂得规避——把"领奖"写成"领奬"，在词中间塞符号，用谐音替换关键词。

**v3（成功版本）**：
> 我做的这个项目主要是想解决中文垃圾邮件的识别这个问题。中文这种邮件的处理一直比较麻烦，邮件里面的文本语义表达本身就比较灵活，词和词之间的边界也不是很明显，再加上发垃圾邮件的人会用各种办法去规避过滤系统，比如说会用谐音字去替换原来的字，或者在词语中间加进一些奇怪的符号。这样一来，原来那种基于关键词匹配和人工规则的方法效果就比较差了，在准确率和实时性上都不太能满足实际的需求。

### 关键差异

- **v3 没有破折号**：从 `棘手——可发送者...` 改成"麻烦，邮件里面的文本..."
- **v3 第一人称**："我做的这个项目"代替"中文垃圾邮件已成为..."
- **v3 冗余表达**："比较麻烦"+"不太能满足"两次表达同一意思
- **v3 模糊限定**："比较麻烦""不是很明显""比较差""不太能"
- **v3 一逗到底**：长句用逗号串起来，不分多个短句

## v3 之后的剩余优化空间（27% → 11%）

v3 仅 3 段验证时还有 17 个百分点的剩余空间，归因到 3 类段落：

1. **数字密集段**（如实验结果，连续多个百分比）。v3.1 SKILL 加入"数字模糊化"技巧
2. **原理解释段**（如 CNN 层结构）。v3.1 SKILL 加入"我研究了一段时间才搞明白"模板
3. **总结/展望段**（论点均衡铺陈）。v3.1 SKILL 加入"主观评价 + 不规整列举"

详见 SKILL.md "进阶优化"章节。

### v9：全文应用 + 格式保留替换（终版）

- **AIGC 率：11%（降 44 pp）**
- 全文 22000 字按 v3 + v3.1 进阶规则全部改写
- 用 `replace_docx.py` 把改写后的内容**保留格式塞回原 docx**
- 保留：表格、图片、引用上标 [N]、字体、目录、参考文献、Heading 样式
- 一次替换 95 段正文，多格式段（关键词/英文标题/Keywords）自动跳过保护

**v9 vs v3 的关键差异**：

| 维度 | v3（仅 3 段） | v9（全文） |
|------|------------|-----------|
| 改写覆盖 | 3 段 ≈ 3000 字 | 95 段 ≈ 21000 字 |
| 数字段技巧 | 未应用 | 应用（"大概""左右"包裹） |
| 原理段技巧 | 未应用 | 应用（"我研究了一段时间才搞明白"） |
| 总结段技巧 | 未应用 | 应用（主观评价 + 不规整列举） |
| 格式保留 | 文本输出 | docx 保留替换 |
| 引用 [N] 上标 | — | 21 处全部正确 |
| AIGC 率 | 27% | **11%** |

**为什么从 27% 又降了 16 pp**：
- 全文应用让 v3 规则覆盖率从 14% 提升到 95%
- 进阶优化命中了 v3 漏掉的 3 类难段
- 格式保留替换没有引入新的 AI 痕迹（python-docx 不会"猜"内容）

## 教训

1. **不要相信 LLM 自己的"口语化"判断**。它的口语化是 LLM 集体的口语化，不是某个学生的真实口语
2. **数据驱动，不是直觉驱动**。每一条规则都要有"实测降了几个百分点"的证据
3. **AB 测试胜过盲改全文**。v3 先验证 3 段（约 3000 字）就发现策略对了，再扩展全文比直接全改安全
4. **真实研究细节是核武器**。LLM 编不出来"我曾把 max_len 从 100 改到 300"这种事，作者本人提供 1-2 句真实研究路径，每段能再降 3-5%
